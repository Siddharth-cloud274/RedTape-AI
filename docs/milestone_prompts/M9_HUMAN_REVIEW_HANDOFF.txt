10. Current generated PDF draft, if available
11. Current document version
12. Official sources and verification dates
13. Applicable online or offline procedure
14. Information that remains unverified

Distinguish clearly between:

- User-provided information
- Confirmed structured applicant facts
- Verified government requirements
- AI-generated explanations
- Unverified or conflicting information

Never turn inferred information into
confirmed applicant information.

Do not mark a requirement complete unless
the existing validated evidence supports it.

If required information remains missing,
show what must be resolved.

For services without M8 PDF support,
allow a guidance-only review summary,
but never pretend that a form was generated.

==================================================
PHASE C — REVIEW STATE MACHINE
==================================================

Create a controlled review workflow.

Suggested review states:

- review_not_started
- review_pending
- review_in_progress
- review_changes_requested
- review_blocked
- review_ready
- user_approved
- approval_invalidated
- handoff_ready
- handoff_opened

These states represent RedTape AI's
internal preparation workflow.

They do not represent government
application status.

Backend rules:

1. Only validated transitions are allowed.
2. User approval requires explicit action.
3. The AI cannot approve for the user.
4. Invalid state transitions return errors.
5. Incomplete drafts cannot be approved
   as complete application packages.
6. Corrections invalidate relevant approvals.
7. Stale document versions cannot be approved.
8. Failed approval writes must not leave
   inconsistent state.
9. A review may be reopened for corrections.
10. State persists after backend restart.

Keep review state separate from
government submission state.

Do not create a fake government
"Application Approved" status.

PHASE D — EXPLICIT HUMAN APPROVAL
==================================================

Implement a user-controlled approval checkpoint.

Before approval, display:

- Application summary
- Current document version
- Collected applicant information
- Missing information warnings
- Verified source references
- Applicable submission procedure
- Clear draft status

Require the user to:

1. Open or inspect the current review summary.
2. Confirm that the entered details are correct.
3. Acknowledge that the document has not
   been officially submitted.
4. Explicitly click an approval control.

Approval must be opt-in.

Do not preselect approval checkboxes.

Do not infer approval from:
- Sending a message
- Downloading a PDF
- Opening a source
- Clicking an external portal link

Suggested approval declaration:

"I have reviewed the application information
and approve this draft for my own use.
I understand that it has not been submitted
to the government."

Approval must be bound to:

- Conversation ID
- Review ID
- Document ID, if applicable
- Document version
- Document content hash, if available
- Relevant applicant-data snapshot/hash
- Timestamp
- Explicit user action

No Gemini-generated message may set
user_approved automatically.

PHASE F — GOVERNMENT HANDOFF ENGINE
==================================================

Implement two submission guidance modes.

MODE 1: ONLINE HANDOFF

Examples:
- Applicable WB municipal trade licence
- Applicable FSSAI registration

The system should:

1. Identify the official portal from M7 evidence.
2. Validate the exact official URL.
3. Confirm service and jurisdiction applicability.
4. Display relevant documented submission steps.
5. Explain what information or documents the
   user may need to provide on that portal.
6. Provide an explicit "Open Official Portal" action.
7. Open the link only after the user's click.
8. Explain that the user completes login,
   OTP, CAPTCHA and final submission there.

No automated submission is allowed.

MODE 2: OFFLINE HANDOFF

Examples:
- Kolkata Collectorate domicile certificate
- Kolkata Collectorate income certificate

The system should:

1. Identify the applicable issuing office.
2. Display verified official instructions.
3. Show the relevant form and supporting
   document checklist.
4. Display submission method and document
   copy requirements when sourced.
5. Display office details when verified.
6. Provide an official source link.
7. Allow downloading the approved draft.
8. Explain that the applicant completes
   signature and physical submission.

Do not offer "Apply Online" when the
verified workflow requires offline submission.

If submission mode is unknown,
show "Submission method not verified".

Do not guess an authority or office address.
